# Спека: «Распознать файл» из контекстного меню трея

Статус: proposal (не реализовано).
Целевая версия демона: 0.3.0.
Затрагиваемый код: только `src/whisper-hotkeyd.cpp` (+ версия в main, документация).
`kit/` не затрагивается (скрипт демоном больше не вызывается).

---

## 1. UX-флоу

1. ПКМ по иконке в трее → пункт **«Распознать файл»** (кликабелен только в покое).
2. Открывается системный (нативный KDE) диалог выбора файла:
   `QFileDialog::getOpenFileName`, фильтр — см. §3.
3. Пользователь выбрал исходник → сразу открывается второй системный диалог:
   `QFileDialog::getSaveFileName`, **«Куда сохранить текст»**, фильтр `Текстовые файлы (*.txt)`.
   Путь по умолчанию: **та же папка, что и исходник, то же имя, расширение `.txt`**
   (`/a/b/лекция.mp3` → `/a/b/лекция.txt`). Нативный диалог сам спросит о перезаписи.
   Отмена второго диалога — отмена всего сценария (без распознавания).
4. Оба диалога закрыты → старт пайплайна (§5–§7):
   - бип `beep_start`, уведомление «Распознавание файла…»;
   - оверлей в режиме «распознавание» (спиннер), пункт меню превращается
     в **«Остановить распознавание файла»**;
   - в статусе трея/тултипе показывается прогресс (§7).
5. Успех: бип `beep_stop`, уведомление «Готово: `<путь к txt>`» (первые ~200 символов
   текста в теле уведомления), log-строка `файл распознан: <src> -> <dst>`.
6. Отмена: бип не играет, уведомление «Распознавание отменено»
   + (если чанковый режим, §6) «сохранена часть: N%».

Осознанно НЕ делаем (чтобы не размывать фичу):
- не кладём текст в буфер обмена (цель — файл, clipboard может быть занят);
- не пишем в `history.txt` и не архивируем в `dictations/` (источник и так уже
  на диске у пользователя);
- не перенаправляем в оверлей никакого текста.

## 2. Точки интеграции в коде

- `TrayIndicator` (`src/whisper-hotkeyd.cpp:387`):
  - новый пункт меню после «Показывать уведомления», до «Настройки...»;
  - владеет двумя QFileDialog-сценариями; на успехе шлёт сигнал
    `fileChosen(QString src, QString dst)` наружу;
  - знает о занятости демона (см. ниже) и переключает пункт
    «Распознать файл» ⇄ «Остановить распознавание файла».
- `DictationController`: новый публичный API
  `startFileTranscription(src, dst)` / `cancelFileTranscription()`.
  Вся оркестрация (ffmpeg → whisper-cli → запись txt) живёт здесь,
  потому что владеет состоянием, оверлеем, beep/notify/log.
- Состояние: `DictationController::State` расширяется значением
  `FileTranscribing`. Поведение:
  - `toggle()` по Ctrl+E в `FileTranscribing` → игнор (как сейчас в `Transcribing`),
    без бипа;
  - «Распознать файл» неактивен в `Recording` / `Transcribing` / `FileTranscribing`
    (кроме как в режиме «Остановить…»);
  - из `Recording`/`Transcribing` диалоги не открываем вообще.
- Связка в `main()`: `connect(&tray, &TrayIndicator::fileChosen, &controller, ...)`.
- Статус трея: сейчас `setState(bool active, bool transcribing)` — трёхбуквенных
  состояний уже не хватает. Рекомендуется внутренний enum
  `{ Idle, Recording, Transcribing, FileTranscribing }` и одна точка правки
  в `TrayIndicator::setState`; надпись для файла: «Whisper: распознавание файла»,
  цвет — синий как у распознавания, тултип — «Ctrl+E — начать/остановить диктовку».

## 3. Форматы входа

`whisper-cli` принимает из коробки только **flac, mp3, ogg, wav** (проверено:
`whisper-cli --help` → «supported audio formats: flac, mp3, ogg, wav»).
Контейнеры/кодеки вне этого списка (m4b, aac, mp4, webm, wma, …) whisper-cli
не читает → весь вход гоняем через ffmpeg (он и так обязателен для записи).
Единый путь «всё через ffmpeg» проще, чем ветвление, и даёт 16 kHz mono на
выходе — меньше RAM в whisper и mel.

Фильтр первого диалога:

```
Аудио (*.m4b *.mp3 *.wav *.flac *.ogg *.oga *.opus *.aac *.mp4
        *.webm *.wma *.aiff *.aif *.amr *.mka *.ape);;Все файлы (*)
```

Почему именно эти: mp3, wav, flac, ogg/oga, opus — самые частые; m4b
(аудиокниги), aac, mp4/webm (видео с речью — берём первый аудиодорожек),
wma, aiff/aif, amr, mka, ape — ffmpeg их декодирует без лишних сборок.

Новых зависимостей нет: ffmpeg/ffprobe уже используются демоном; пакеты не
добавляем (правило AGENTS.md).

## 4. Валидация и подготовка (до старта)

1. `QFileInfo(src)`: существует, читается, размер > 0.
2. Длительность: async `ffprobe -v error -show_entries format=duration
   -of csv=p=0 SRC` (та же команда, что `dur()` в скрипте). Не число / < 1 с
   → ошибка «не похоже на аудиофайл» (`beep_err` + notify + log).
   ffprobe_fail → та же ошибка (перехватывает битые/не-аудио файлы,
   переименованные в `.mp3`).
3. Диск под временный wav: `QStorageInfo(tmpDir).bytesAvailable()` ≥
   `длительность_сек × 32 КБ/с × 1.2` (запас). Иначе — ошибка «нет места
   во временном каталоге (~N МБ нужно)».
4. Свободен ли демон: `startFileTranscription()` при активной диктовке —
   no-op + notify (страховка, основная защита — disabled-пункт меню).

## 5. Пайплайн (одиночный режим, ≤ 15 мин)

Конвертация (async QProcess, **никаких waitFor\* в GUI-потоке** — правило проекта):

```
ffmpeg -nostdin -loglevel error -y -i SRC -map 0:a:0 -vn -ac 1 -ar 16000 \
       -c:a pcm_s16le TMPDIR/file-<timestamp>.wav
```

- `-map 0:a:0 -vn` — первый аудиодорожек, обложки/видео в mp4/m4b отбрасываем;
- ресемпл в 16 kHz mono обязателен: whisper сам бы привёл, но тогда его буфер
  будет считаться от исходной частоты (48 kHz stereo = 3× RAM зря);
- временный wav: `~/.local/share/whisper/tmp/filetrans/<ts>.wav`
  (своя подпапка, чтобы не пересекаться с `record.wav` диктовки);
- `-y` безопасен: имя с уникальным timestamp.

Затем whisper-cli — те же флаги, что у диктовки (согласованность языка/промпта):

```
whisper-cli -m <model> -f TMP.wav -l ru --prompt <hotwordPrompt()> \
            -otxt -of TMPBASE -pp -t <nproc>
```

Отличия от диктовки:
- **без `-np`**, с **`--print-progress` (`-pp`)** — нужен прогресс (§7);
  `-np` глушит вывод, парсить будет нечего;
- без таймаута `kFinishTimeoutMs` (он для записи): длинный файл может
  считаться десятки минут — это норма, не зависание.

Готовый `TMPBASE.txt` → `QFile::copy` на выбранный пользователем путь
(с предварительным `QFile::remove(dst)` при существующем — нативный диалог
уже спросил). Затем удалить TMP.wav/TMP.txt.

## 6. Длинное аудио: чанковый режим (> 15 мин)

Зачем (помимо «просто длинный»):
- RAM детерминирована: whisper держит весь PCM float32 + mel в памяти
  (~64 КБ/с + ~32 КБ/с от длительности ⇒ ~0.35 ГБ на час). 10-часовой файл
  одиночным прогоном ≈ 3.5 ГБ + 0.9 ГБ модель — на 8 ГБ машине уже тесно;
- при падении/отмене на 2-м часе не теряем распознанный 1-й;
- прогресс и отмена работают между чанками, не дожидаясь конца.

Порог: `длительность > 900 с` → чанковый режим, иначе одиночный (§5).

Нарезка:
1. Async `ffmpeg -i SRC -af silencedetect=noise=-35dB:d=1.0 -f null -`,
   парсим stderr: пары `silence_start` / `silence_end`.
2. Целевой размер чанка — 600 с. Точка реза для i-го чанка:
   - ближайший `silence_start` к `i×600` в окне ±180 с (420…780);
   - иначе ближайший `silence_start` в пределах 300…1200 с;
   - иначе фикс `i×600` (риск обрезать слово — приемлемо, логируем).
   Тишина на границе ≈ слово не режется, дублей текста не появляется
   (оверлап не делаем — избыточно для v1).
3. Каждый чанк: async `ffmpeg -ss <start> -to <end> -i SRC` (нормальный путь
   с `-ss` до `-i` — точный и быстрый рез) → тот же wav 16 kHz mono →
   whisper-cli (как §5) → результат.
4. Между чанками в выходной файл дописываем `"\n\n"` (разделитель абзацев).

Инкрементальная запись результата: открываем `dst` (`Truncate`) только после
**успешного первого чанка** и дописываем (`Append`) после каждого следующего.
Так при ошибке/отмене середины файл содержит распознанную часть, а при ошибке
на первом чанке не трогаем существующий dst.

Отмена (`cancelFileTranscription()`):
- kill текущего QProcess (ffmpeg или whisper-cli);
- остановить следующий чанк (флаг `m_fileCancel`);
- довести dst до актуального состояния (уже дописано), удалить tmp;
- state → Idle, notify «Распознавание отменено (+ сохранена часть N%)».

Сложность одной нарезки: если все silence-парсеры дали пусто (сплошная речь),
работаем на фиксированных 600 с.

## 7. Прогресс

- Источник 1: stderr whisper-cli, regex `progress\s*=\s*(\d+)` → процент
  внутри текущей единицы работы (чанка или всего файла в одиночном режиме).
  Формат вывода нестабилен между версиями — если распарсить не удалось,
  показываем просто статус без процентов (деградация, не ошибка).
- Итоговый процент:
  - одиночный режим: `p`;
  - чанковый: `(completed_chunks × 100 + p) / total_chunks`.
- Куда показывать: текст `m_status` («Whisper: распознавание файла 37%») и
  тултип иконки. Обновлять не чаще раза в 500 мс (QTimer/throttle), чтобы
  не дёргать трей.
- Прогресс ffmpeg-конвертации не парсим (быстро), показываем статус
  «Подготовка аудио…».

## 8. Обработка ошибок (все пути → state Idle + log)

| Ситуация                          | Действия                                            |
|-----------------------------------|-----------------------------------------------------|
| ffprobe не дал длительности       | beep_err, notify «Не аудиофайл», tmp не создавать   |
| ffmpeg завершился код ≠ 0         | beep_err, notify «Ошибка конвертации аудио», в log последние строки stderr ffmpeg |
| whisper-cli код ≠ 0               | beep_err, notify «Ошибка распознавания, см. журнал» |
| Пустой результат (trim пусто)     | dst не создавать/удалить, beep_err, notify «Ничего не распознано» |
| Нет места под tmp (§4.3)          | notify с размером, старт не выполняем                |
| Пусто на первом чанке             | как «Пустой результат», dst не трогать               |
| Ошибка на чанке N > 1             | beep_err, notify «Ошибка на чанке N/M, сохранено что есть» |

stderr QProcess перенаправляем в log (`logMsg`) — как у диктовки
(`ForwardedErrorChannel` не подходит: хотим свои префиксы `[file-ffmpeg]`,
`[file-whisper]`).

## 9. Временные файлы

- Всё в `~/.local/share/whisper/tmp/filetrans/`:
  `<ts>.wav`, `<ts>.txt` (промежуточный выход whisper), при чанках — `<ts>-c<i>.wav`.
- Очистка в любом исходе (успех/ошибка/отмена): удалить всё созданное в этом
  запуске; при старте — досать осиротевшие файлы старше 24 ч (страховка от
  убитого демона).
- Директорию после себя оставляем (пустую).

## 10. Не-цели (v1)

- Автовставка текста, clipboard, history — нет (§1).
- VAD-модель (`--vad`) — новая зависимость, не ставим.
- Параллельная обработка чанков — последовательно (одна модель в RAM).
- Второй диалог с настройками (язык, модель) — язык/модель как у диктовки.

## 11. План реализации (порядок)

1. Enum статусов в `DictationController` + `TrayIndicator::setState`;
   расширить сигнал `busyChanged`.
2. Пункт меню + два QFileDialog-сценария + сигнал `fileChosen`.
3. `startFileTranscription()`: валидация (§4) + одиночный режим (§5)
   с отменой и очисткой tmp.
4. Прогресс (`-pp`, парсинг, троттлинг) и статусы трея (§7).
5. Чанковый режим (§6) + инкрементальная запись dst.
6. Тесты (§12), `bash -n` не нужен (C++); сборка:
   `cmake -S src -B src/build -DCMAKE_BUILD_TYPE=Release && cmake --build src/build`,
   версия в `main()` → 0.3.0, установка в `~/.local/bin`, рестарт демона.
7. Документация: README.md (пункт статуса), AGENTS.md (описание трея),
   удалить устаревший HANDOFF.md.

## 12. Тесты (ручные, смоук)

1. **mp3, короткий** (~30 с): пункты меню, оба диалога, дефолтный путь
   `имя.txt` рядом с исходником, текст в файле, уведомление, tmp пуст.
2. **Все форматы фильтра**: сгенерировать из имеющегося wav
   (`ffmpeg -i beep_start.wav …` для m4b/aac/opus/…),
   прогнать каждый — распознаётся, ошибок конвертации нет.
3. **Длинный** (≥ 25 мин, подкаст/лекция): чанковый режим, проценты растут,
   RAM стабильна (`ps`/`btop`), TXT дописывается по мере готовности.
4. **Отмена на середине длинного**: файл сохраняет распознанную часть,
   tmp чистый, state Idle, пункт возвращается в «Распознать файл».
5. **Реентерабельность**: во время file-распознавания Ctrl+E игнорируется;
   во время диктовки пункт «Распознать файл» неактивен.
6. **Ошибки**: переименованный `.txt` → `.mp3`, несуществующий путь,
   перезапись существующего txt (диалог спрашивает), путь с кириллицей,
   мало места (проверить расчётом, можно подменой порога).
7. Пустой результат (файл тишины) → dst не создан, уведомление.

## 13. Критерии приёмки

- [ ] Пункт «Распознать файл» есть и открывает нативный KDE-диалог.
- [ ] Все форматы из фильтра распознаются без ручных шагов.
- [ ] Второй диалог по умолчанию предлагает `../<имя_исходника>.txt`.
- [ ] Файл > 15 мин обрабатывается без роста RAM со временем (чанки),
      с прогрессом и рабочей отменой; уже готовая часть не теряется.
- [ ] GUI не блокируется ни на одном шаге (нет waitFor* в GUI-потоке).
- [ ] Любая ошибка завершает сценарий в Idle: оверлей гаснет, tmp чист,
      в логе причина.
- [ ] Новых зависимостей и изменений в `kit/` нет.
